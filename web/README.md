# plain-work 文字精修网站

一个支持文本与文件的降 AI 味工具。免费规则模式在浏览器中运行；深度改写使用用户本次填写的 DeepSeek API Key。

## 已实现

- 双栏输入与输出、示例、字数、复制、下载、取消、进度与错误提示。
- TXT 上传后下载 TXT；保留 UTF-8 BOM、带 BOM 的 UTF-16 及原有换行。
- DOCX 上传后下载 DOCX；原包中的样式、图片、关系和表格结构保留，修改正文、页眉页脚、脚注尾注中可安全编辑的文字节点。
- 含字段、公式、修订、内容控件或图形的段落跳过；超链接文字保留。扫描图片不做 OCR。
- 模型模式提供通用、文档、科研、邮件场景及轻度/适度选项；规则模式采用同一套保守规则，场景与强度按钮在该模式禁用。
- 模型输出逐片段核对数量、非空与长度，并检查数字、链接和代码是否变化；检查失败则不生成部分文件。
- 全部处理完成后再提供结果。取消或某批失败时不导出半成品；已经送出的模型请求仍可能产生 API 费用。

单文件最多 10 MB，可改写文本最多 40,000 个 UTF-16 字符。Word 解压后最多 30 MB、2000 个条目。旧版 `.doc`、PDF、RTF 不支持；`.doc` 请先另存为 `.docx`。TXT 不支持的旧编码请先转为 UTF-8。

## 本地启动

需要 Node.js 22.13+。

```console
npm ci
npm run dev
```

默认预览地址 `http://127.0.0.1:5173/`。没有模型密钥也可以使用规则精修。

```console
npm test
npx tsc --noEmit
npm run build
```

生产构建输出到 `dist/`，Sites Hosting 配置见 `.openai/hosting.json`。该 ID 绑定本项目所有者的部署；其他人复制代码时应注册自己的站点并更新 ID，不要向此 ID 发布。

## 接入 DeepSeek

1. 在 [DeepSeek 平台](https://platform.deepseek.com/)创建 API Key，按平台要求开通 API 额度。
2. 网页打开“改写设置”，选择“DeepSeek 深度改写”。
3. 临时填写自己的密钥，选择场景与修改程度，点击“开始精修”。
4. 文字经本站 `/api/rewrite` 转发到固定的 `https://api.deepseek.com/chat/completions`；当前使用官方文档列出的 `deepseek-flash`，关闭思考模式并请求 JSON 输出。刷新页面会清除密钥。

接口约定核查于 2026-10-26：[官方接入](https://api-docs.deepseek.com/)、[JSON 输出](https://api-docs.deepseek.com/guides/json_mode/)、[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)。后续模型名称与计费请以平台实时文档为准。

密钥只保存在 React 页面内存中，并随单次请求传至本站后端和 DeepSeek。应用代码不将密钥或文本写入日志、数据库、localStorage 或 sessionStorage，也不提供文本历史。托管平台和模型服务自身的数据处理规则仍适用。

当前没有运营方公共密钥、账户余额或真实支付功能。调用费用由填写密钥的用户向 DeepSeek 承担。后续商业化方案见根项目 `docs/product-plan.md`。

## 文件与改写边界

DOCX 以文字节点为修改单位，优先保留字符样式和原有结构。跨样式的完整句子可能被分成多个片段，因此会牺牲一部分整体改写能力。文字长度变化仍可能改变分页；不是逐页排版复刻。预览框只展示可处理文字，不模拟 Word 页面。

规则模式只处理少量明确冗余的引导语和表达，不负责段落级重写，也不自动删除所有对照或否定。没有匹配时返回原文。深度模式通过提示与局部检查降低语义偏移，仍无法自动证明事实、引用和否定完全保真；正式使用前需对照原稿复核。

测试覆盖编码/换行、代码保护、DOCX 粗体/表格/图片与字段保留、异常文档、模型参数及失败返回。模型接口使用模拟响应测试；尚未使用真实付费密钥验证效果和成本。浏览器已验证文本精修、Word 上传和同格式下载，下载文件经过包内结构与文本核对。
