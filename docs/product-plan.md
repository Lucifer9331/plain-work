# 网站接入模型与收费方案

日期：2026-10-26。本文是产品建议与后续设计，收费功能尚未实现，不是运营效果或收益承诺。

## 当前版本

| 方式 | 用户如何使用 | 谁承担模型费用 | 当前状态 |
| --- | --- | --- | --- |
| 规则精修 | 输入文本或上传文件，直接处理 | 不调用模型 | 已实现 |
| 自带密钥 | 在网页临时填写 DeepSeek API Key | 密钥所属的模型账户 | 接口已实现，模拟响应验证通过；尚无真实密钥效果与成本测试 |
| 托管付费改写 | 用户购买额度，平台调用运营方模型账户 | 运营方先承担调用成本，再由套餐覆盖 | 后续方案 |

当前站点是所有者私有预览；代码公开。开放给更多人之前，应先决定访问范围、服务承诺与额度策略。

## 如何接入大模型

自带密钥模式：用户在 [DeepSeek 平台](https://platform.deepseek.com/)申请 API Key，并按平台要求开通 API 额度；网页“改写设置”中选择深度改写并填写密钥即可。本站后端将文本和编辑指令发送给固定的 DeepSeek 官方接口，不接受用户任意指定转发地址。

运营方托管模式：密钥保存在服务器的秘密变量中，由后端读取。浏览器只提交文字和用户身份；后端确认额度后调用模型。运营方密钥不能发给浏览器，不能放入公开 GitHub 仓库。将前端按钮改成“付费用户可见”不足以限制后端使用。

API 需要模型平台的可用额度。先用少量、脱敏的真实样本测试，并记录输入、输出 token、耗时、失败率与人工复核结果。当前代码采用 `deepseek-flash` 和 JSON 输出；模型名称、接入约定及当前价格请在 [DeepSeek 官方文档](https://api-docs.deepseek.com/)与控制台核对。

## 建议的产品分层

免费版提供基础规则精修和同格式下载，让用户先完成一次真实任务。自带密钥模式服务希望自行控制模型账户和费用的用户，也能帮助项目验证深度改写需求。

托管付费版可出售明确的字数或文档额度，重点提供无需配置密钥、较长文档、格式保留、可核对的改写与稳定服务。初期按量套餐更容易估算成本；在了解实际使用分布前，不建议承诺无限量。

定价依据应来自实测：单次模型成本、长文拆分次数、失败或重试、托管成本、支付渠道费用以及支持成本。中文字符数与 token 数不同，不能直接拿每千字售价与每千 token 单价相减来计算利润。

原有代码以 MIT 公开，其他人可以自行部署。付费价值应来自托管便利、质量与服务；公开许可证无法保证竞争壁垒。可以保留开源工具，另建托管服务，不必把当前公开技能突然锁住。

## 托管收费需要补齐的功能

1. 用户身份与服务端权限检查；具体访问方案与托管平台能力一致。
2. 订单、额度账本与余额预留，所有变更可追踪并保持幂等。
3. 支付渠道服务器签名验证的 webhook；不能信任浏览器“支付成功”页面。
4. 调用前估算并预留额度，成功后结算，失败时按实际规则释放；防止重复请求和并发超额。
5. 请求限速、单次及账户用量上限、异常费用告警、退款与客服流程。
6. 与实际数据流一致的隐私说明、服务条款及用户文件处理政策。

这些功能需要独立实现和验收。当前 `/api/rewrite` 仅转发调用者自己的密钥，不承担付费账户判断。

## 是否现在测试付费

现在先验证文字质量、文件完整性和单次成本，再找少量用户完成真实任务并询问其愿意为何付费。无需为这一版接入真实收款，也无需为了测试而购买大额模型额度。

支付开发阶段使用所选渠道的沙箱，测试成功、失败、取消、回调重发、重复订单和退款。[Stripe 测试文档](https://docs.stripe.com/testing)说明沙箱交易不会转移资金；这只是测试机制示例，具体渠道应根据主体、地区和可用能力决定。正式收款前需完成服务端额度闭环，并在渠道允许的上线流程中验证。
