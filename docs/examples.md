# 修改示例与保留反例

下列均为本项目构造的教学示例。事实只在各自设定中成立，不能直接移入真实项目。

| 场景 | 原句 | 设定或问题 | 修改稿 |
| --- | --- | --- | --- |
| 对话 | 你抓住了本质。这不是工具问题，而是认知问题。 | 无支持该归因的材料 | 删去赞许和归因，直接分析用户实际遇到的步骤或错误；有材料后再给结论。 |
| 文档 | 我们要用的不是简单脚本，而是一套强大的自动化方案。 | 实际功能是读取 CSV 并输出 JSON | 脚本读取 CSV 文件并输出 JSON。 |
| 复现 | 本项目完整复现了论文效果。 | 仅运行一个推理样例 | 已运行一个推理样例。完整测试集评估尚未完成。 |
| 科研 | 方法显著优于基线。 | A=81.2%，B=80.9%，单次运行无检验 | 本次运行中，A 的准确率为 81.2%，B 为 80.9%。尚未进行显著性检验。 |
| 邮件 | 不是催促，而是希望双方共同高效推进。 | 同事，周五前需确认排期 | 想确认一下排期。我们周五前需要定下来，你方便在那之前回复吗？ |
| English docs | Seamlessly unlock powerful data transformation capabilities. | CSV → JSON，已核实 | Convert CSV files to JSON. |
| English mail | I sincerely hope this email finds you exceptionally well. I am writing to kindly request your valuable feedback. | 已知请求：周五前审阅草稿 | Could you review the draft by Friday? |

## 这些内容需要保留

- “不支持 Python 3.8”：运行条件。
- “不能由相关性推出因果关系”：科学结论的边界。
- “这周无法交付”：实际承诺范围。
- “谢谢您审阅申请材料”：可能符合导师或首次联系的关系。
- “与基线相比，峰值内存降低”：有数据支持的真实比较。
- `if not authorized: raise PermissionError(...)`：程序行为。
- 类型、验证、事务、文档中的标题与列表：有实际功能时保留。

## 用编辑备注容纳事实缺口

输入：“模型效果很好，请写得自然一点。”

可给：“目前这句话缺少指标和对照，无法说明效果。请补充数据集、指标和运行条件。”如果用户只要求语气调整，可给有限的文字修改并说明缺口。补造数字会让文稿更具体，也更不可信。

输入：“请保留 `python run.py --seed 42`，删掉前面的套话。”

修改时逐字保护命令。发现命令可能有错时，另外注明依据，不能把运行参数的变化藏进风格编辑。
