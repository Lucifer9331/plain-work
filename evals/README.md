# 评估规程

本目录提供 18 个构造案例，覆盖五个技能的目标行为及保留反例。它们用于回归审阅，尚未构成真实用户数据集或效果基准。

[首版自查](self-check.md)保留了同一编写 agent 的示范输出及一个承诺边界问题的修正。它是可复核的示例记录，不能替代独立盲评。

## 运行一次评估

1. 从 `cases.json` 选一个案例，将 `prompt` 和 `input` 连同对应技能交给模型。`context` 提供允许使用的事实与任务边界。
2. 保留模型、日期、技能版本和完整输出。另做一次同条件、无技能的基线；随机化两个版本的顺序，尽量不让评审者知道来源。
3. 评审者先查看 `must_preserve`、`must_avoid` 和 `pass_criteria`，逐项判断。记录原句、改句和理由，避免只凭“更像人”的印象。
4. 用下面的维度比较。出现事实或行为回归时，直接判为失败；其余维度分开记录，不把“更短”当作总目标。

模型可作为第二位评审，但风格偏好可能相关，仍需人工抽查。单人自评应注明，不能称为独立盲测。实际材料请先取得授权并匿名化；本地结果可放 `local-results/`，默认不入 Git。

| 维度 | 通过的证据 | 失败或待核实 |
| --- | --- | --- |
| 事实/行为保真 | 数字、命令、否定、承诺、API 和引用均保持正确 | 任何编造、遗漏约束、改变错误语义 |
| 任务完成度 | 给出用户要求的稿件或审阅意见 | 只讲写作原则，没有完成材料 |
| 具体性 | 要点能指向材料中的对象与依据 | 泛化赞美、无来源细节、空泛拔高 |
| 场景适配 | 符合读者、渠道和作者语气 | 邮件失礼、论文过度口语化、项目约定被破坏 |
| 重复负担 | 去除了无作用的重复，必要导航仍在 | 用新口头禅替换旧模板、删掉必要说明 |

建议记录：`case_id`、`model`、`date`、`commit`、`condition`、`output`、各维度 `pass/fail/uncertain`、`evidence`、评审者身份类别及是否盲评。

`python scripts/validate.py` 只检查案例结构与包内链接；行为是否通过需要实际输出及上述审阅证据。仓库首版没有自动调用模型的代码，也没有宣称获得盲测提升。
